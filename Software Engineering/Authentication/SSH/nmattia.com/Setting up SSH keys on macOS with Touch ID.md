# [Setting up SSH keys on macOS with Touch ID](https://nmattia.com/posts/2026-10-19-setting-up-ssh-keys-touch-id/)
* Identities are managed by the `sc_auth` command (`sc` stands for `Smart Card`)
  * They are called `CryptoTokenKit` identities or `CTK` for short
  * These are equivalent to private keys stored on the "Secure Enclave"
  * These identities can be introspected by executing the following command `sc_auth list-ctk-identities`
* These identities can be created using the following command: `sc_auth create-ctk-identity -l <label> -k <key type> -t <protection>`
  * Key type defines the elliptic curve to use (one of `p-256`, `p-384`, `p-521`, `p-256-ne`, `p-384-ne`)
    * `ne` suffix means "Non-Extractable" meaning the key is generated by the "Secure Enclave" and cannot be extracted from the "Secure Enclave"
  * `protection` is either `bio` or `none`
    * `bio` requires biometrics (Touch ID)
    * `none` allows programs to silently use SSH
  * The `ssh` program does not know how to use these `CTK` identities directly
    * Apple as a small translation later defined in `/usr/lib/ssh-keychain.dylib`
      * `ssh-add -K -S /usr/lib/ssh-keychain.dylib`
* When an SSH connection is initiated, the remote server accepts one of the public keys offered by the agent
  * Remote server challenges the client to prove its identity
  * SSH agent calls `_sk_sign` to create a signature with the private key matching the accepted public key + the remote server's "challenge"
  * "Secure Enclave" receives the signature, prompts Touch ID approval
  * If approved, signature is returned form the "Secure Enclave" and eventually forwarded to the remote server
